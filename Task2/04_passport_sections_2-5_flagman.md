# Паспорт инициативы №1. Разделы 2–5

## Раздел 2. Постановка

| Поле                        | Содержание                                                                                                                                                                                          |
|-----------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Бизнес-действие             | Приоритизация очереди финмониторинга. Решение по каждой операции (эскалация, отказ, снятие) принимает человек по действующей процедуре.                                                             |
| Объект и единица решения    | Операция по счёту.                                                                                                                                                                                  |
| Момент                      | Near-real-time при появлении операции; пачечный пересчёт очереди; разбор человеком.                                                                                                                 |
| Операция                    | Ранжирование / бинарная классификация с сортировкой по скору.                                                                                                                                       |
| Модальность                 | Таблица + текст (назначение платежа).                                                                                                                                                               |
| Выход модели                | Риск-скор 0–1, позиция в top-K, набор сработавших признаков.                                                                                                                                        |
| Бизнес-выход                | Очередь с приоритетом и пояснением. Не блокировка.                                                                                                                                                  |
| Источник правильного ответа | Эскалация (слабый след), исход расследования, подтверждённые случаи (единицы), плюс разметка контрольной выборки.                                                                                   |
| Конвейер                    | Детерминированные: правила, справочники, лимиты, списки. Обучаемые: скоринг, эмбеддинги текста. Человек: финальное решение.                                                                         |
| Альтернативные постановки   | Классификация «эскалация / не эскалация»; unsupervised-аномалии; только правила + сумма. Различающий вопрос: что оптимизируем — precision@K, пропущенные подтверждённые случаи или снятую нагрузку? |

## Раздел 3. Оценка качества

| Поле                    | Содержание                                                                                                                                                                              |
|-------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Бизнес-метрика          | Доля подтверждённых схем в разобранной верхушке очереди; снятая нагрузка на службу; снижение пропущенных подтверждённых случаев.                                                        |
| Положительный класс     | Операция, которая при разборе признана требующей эскалации/отказа по действующей процедуре (не «схема» в юридическом смысле, если эталона нет).                                         |
| Метрика под решение     | **Precision@K** и **yield@K** при K, равном пропускной способности; **recall** на контрольной выборке. ROC AUC — вспомогательно, не как основная метрика.                               |
| Baseline                | Текущие правила + приоритизация по сумме.                                                                                                                                               |
| Проверочная выборка     | Стратифицированная контрольная выборка, размеченная экспертами, плюс отложенная часть разобранной очереди. Оценка на контрольной выборке честная потому, что она не отбиралась моделью. |
| Рабочая точка           | Top-K, где K ≈ 10 тыс. операций/мес (пропускная способность службы).                                                                                                                    |
| Показатели в этой точке | Precision@K, yield@K, нагрузка на человека; сравнение с baseline.                                                                                                                       |
| Цена ошибок             | Пропуск — регуляторный риск и претензии; ложное срабатывание — потеря времени и риск жалобы/оттока. Обе цены учитываются в guardrail.                                                   |
| Guardrails              | Доля ложных блокировок и жалоб не хуже текущей (около 600 приостановок/мес, 120 жалоб).                                                                                                 |

## Раздел 4. Готовность данных

| Поле                        | Содержание                                                                               |
|-----------------------------|------------------------------------------------------------------------------------------|
| Решение                     | Приоритизация очереди.                                                                   |
| Объект и гранулярность      | Операция.                                                                                |
| Источник и владелец         | Транзакционный журнал, справочники, история. Владелец — ИТ и финмониторинг.              |
| Источник правильного ответа | Следы разной надёжности + контрольная выборка.                                           |
| Доступность признаков       | Все признаки доступны в момент решения.                                                  |
| Разметка                    | Программа: контрольная выборка + разобранная очередь; гайдлайн и оценка согласованности. |
| Смещение отбора             | Критично; корректируется контрольной выборкой и стратификацией.                          |
| Репрезентативность          | Стратификация по сегментам, суммам, каналам.                                             |
| Объём                       | Большой по операциям, единицы по сильным меткам — это и есть дефицит.                    |
| Качество                    | Требует аудита справочников и обработки шумного текста.                                  |
| Право использовать          | Комплаенс и DPO; контур и основание — до старта.                                         |
| **Вердикт**                 | **Разрыв с планом закрытия** — закрывается программой разметки.                          |

## Раздел 5. Карточка эксперимента

| Поле                            | Содержание                                                                                                                                 |
|---------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------|
| Где именно теряем               | На операциях, которые не попадают в пороговые правила, и на структурных схемах (транзит, дробление), которые правила не улавливают.        |
| Гипотеза причины                | Модель на слабых метках + структурные признаки даст более высокий precision@K, чем приоритизация по сумме, и не ухудшит ложные блокировки. |
| Конкурирующие объяснения        | Прирост даёт не модель, а просто пересортировка по сумме; контрольная выборка слишком мала; графовые признаки не работают на этом потоке.  |
| Рычаг                           | Признаки (структурные, текстовые) · модель (бустинг vs граф) · порог top-K · постобработка.                                                |
| Дешёвый различающий эксперимент | Сравнить на одной и той же контрольной выборке: (а) правила + сумма, (б) правила + бустинг, (в) правила + бустинг + графовые признаки.     |
| Ожидаемый эффект                | Прирост precision@K над baseline на согласованную величину; сохранение guardrail.                                                          |
| Стоимость проверки              | Время экспертов на разметку, вычислительные ресурсы на обучение, 4–6 недель.                                                               |
| Критерий остановки              | Если бустинг не даёт прироста над baseline на контрольной выборке — гипотеза неверна, возвращаемся к данным/постановке.                    |
