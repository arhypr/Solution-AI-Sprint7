## Раздел 3. Оценка качества

### 3.1. Единое определение Precision@K

**Precision@K** — доля операций в верхушке очереди (top-K), по которым эксперт финмониторинга по действующей процедуре
**нашёл основания для эскалации на расследование или для отказа в проведении операции**.

Это определение используется во всех артефактах проекта — в паспорте, плане пилота, ADR. Оно сознательно шире, чем
«подтверждённая схема»:

- Эксперт на разборе ищет именно **основания для эскалации или отказа**, а не формальное подтверждение схемы.
- Формально подтверждённые схемы — единицы, появляются с лагом в месяцы, и на горизонте пилота их слишком мало для
  статистически значимого сравнения.
- Поэтому Precision@K считается по экспертной разметке «есть основания / нет оснований», а **подтверждённые схемы
  отслеживаются отдельно** как lagging-метрика (см. 3.4).

**Как считается на пилоте.** Берутся top-K из двух очередей — пилотной (модель + правила) и контрольной (правила +
сумма) — при **одинаковом K**. Одни и те же операции размечаются независимым экспертом, который **не знает**, из какой
очереди операция (слепой дизайн). Precision@K = доля операций с основаниями в каждой очереди. Разница между очередями —
эффект модели.

### 3.2. Метрики под решение

| Поле                    | Содержание                                                                                                                                                                                    |
|-------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Бизнес-метрика          | Доля операций в разобранной верхушке очереди, по которым есть основания для эскалации или отказа; снятая нагрузка на службу; снижение пропущенных подтверждённых случаев (отдельно, lagging). |
| Положительный класс     | Операция, по которой эксперт по действующей процедуре нашёл основания для эскалации на расследование или для отказа. **Не** «подтверждённая схема» — это отдельная метрика.                   |
| Метрика под решение     | **Precision@K** по определению 3.1; **yield@K** (абсолютное число операций с основаниями в top-K); **recall** на контрольной выборке. ROC AUC — вспомогательно.                               |
| Baseline                | Текущие правила + приоритизация по сумме.                                                                                                                                                     |
| Проверочная выборка     | Стратифицированная контрольная выборка, размеченная экспертами (по определению 3.1), плюс отложенная часть разобранной очереди. Оценка честная потому, что выборка не отбиралась моделью.     |
| Рабочая точка           | Top-K, где K ≈ 10 тыс. операций/мес (пропускная способность службы).                                                                                                                          |
| Показатели в этой точке | Precision@K, yield@K, нагрузка на человека; сравнение с baseline при **одинаковом K** и **одной и той же разметке**.                                                                          |
| Цена ошибок             | Пропуск — регуляторный риск и претензии; ложное срабатывание — потеря времени и риск жалобы/оттока.                                                                                           |
| Guardrails              | Доля ложных блокировок и жалоб не хуже текущей (около 600 приостановок/мес, 120 жалоб).                                                                                                       |

### 3.3. Что не является метрикой пилота

- **Число формально подтверждённых схем** — слишком редкое и запаздывающее событие. Отслеживается отдельно (3.4), не
  используется для решения о пилоте.
- **Средний скор модели** — не отражает качество ранжирования.
- **Accuracy на всём потоке** — бессмысленна при сильном дисбалансе классов.

### 3.4. Lagging-метрика: подтверждённые схемы

Отслеживается **отдельно** от Precision@K:

| Что                                                    | Как                                                   | Зачем                                                                                                  |
|--------------------------------------------------------|-------------------------------------------------------|--------------------------------------------------------------------------------------------------------|
| Число формально подтверждённых схем в верхушке очереди | По факту завершения расследований (лаг — месяцы)      | Длинный горизонт: подтверждает, что модель не просто воспроизводит процедуру, а находит реальные схемы |
| Доля подтверждённых схем, которые попали в top-K       | Сравнение с контрольной очередью на длинном горизонте | Проверка recall на редком классе                                                                       |
| Лаг от операции до подтверждения                       | Средний и распределение                               | Планирование горизонта оценки                                                                          |

Эти метрики не входят в критерии успеха пилота (слишком долго), но входят в мониторинг прода.

## Раздел 5. Карточка эксперимента

| Поле                            | Содержание                                                                                                                                                               |
|---------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Где именно теряем               | На операциях, которые не попадают в пороговые правила, и на структурных схемах (транзит, дробление), которые правила не улавливают.                                      |
| Гипотеза причины                | Модель на слабых метках + структурные признаки даст более высокий Precision@K (по определению 3.1), чем приоритизация по сумме, и не ухудшит ложные блокировки.          |
| Конкурирующие объяснения        | Прирост даёт не модель, а просто пересортировка по сумме; контрольная выборка слишком мала; графовые признаки не работают на этом потоке.                                |
| Рычаг                           | Признаки (структурные, текстовые) · модель (бустинг vs граф) · порог top-K · постобработка.                                                                              |
| Дешёвый различающий эксперимент | Сравнить на одной и той же контрольной выборке при одинаковом K и одной разметке: (а) правила + сумма, (б) правила + бустинг, (в) правила + бустинг + графовые признаки. |
| Ожидаемый эффект                | Прирост Precision@K над baseline на согласованную величину; сохранение guardrail.                                                                                        |
| Стоимость проверки              | Время экспертов на разметку, вычислительные ресурсы на обучение, 4–6 недель.                                                                                             |
| Критерий остановки              | Если бустинг не даёт прироста над baseline на контрольной выборке — гипотеза неверна, возвращаемся к данным/постановке.                                                  |
