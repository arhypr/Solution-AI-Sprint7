# Оценка готовности данных по трём инициативам

Чек-лист — раздел 4 паспорта инициативы. Вердикт один из четырёх: «Готово», «Можно начинать пилот», «Разрыв с план
закрытия», «Заблокировано».

## Инициатива 1. Выявление подозрительных операций (флагман)

| Поле                                 | Оценка                                                                                                                                                                                                                             |
|--------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Решение, которое поддерживают данные | Приоритизация очереди финмониторинга: риск-скор операции для сортировки, а не вердикт «схема / не схема».                                                                                                                          |
| Объект и гранулярность               | Операция по счёту. Одна запись — одна операция с признаками транзакции и текстом назначения платежа.                                                                                                                               |
| Источник и владелец                  | Транзакционный журнал, справочники тарифов и лимитов, история взаимодействия с клиентом. Владелец — ИТ-блок и служба финансового мониторинга; доступ через DPO и комплаенс.                                                        |
| Источник правильного ответа          | Три следа разной надёжности: отметка «эскалировано на расследование» (~400/мес), исход расследования, формально подтверждённые случаи (единицы, лаг — месяцы). Готового эталона нет.                                               |
| Доступность признаков в проде        | Все транзакционные поля доступны в момент принятия решения. Текст назначения платежа — в свободной форме, доступен, но требует обработки.                                                                                          |
| Разметка                             | На старте разметки «схема / не схема» нет. Планируется разметка вероятностной контрольной выборки экспертами финмониторинга по гайдлайну, с оценкой согласованности между разметчиками.                                            |
| Смещение отбора                      | **Критично.** Исторически проверяли только операции, отобранные пороговыми правилами и внешними сигналами. Непроверенная операция не равна чистой. Обучение только на проверенных данных воспроизведёт логику существующих правил. |
| Репрезентативность                   | Не покрыты сегменты, которые никогда не попадали в пороговые правила. Контрольная выборка должна быть стратифицирована по сегментам, суммам и каналам.                                                                             |
| Объём                                | Общий объём операций большой (20–25 млн/мес). По важному классу (подтверждённые схемы) — единицы. Это и есть точный дефицит: не «мало данных», а мало **сильных меток** по редкому классу при смещённом отборе.                    |
| Качество                             | Пропуски и противоречия в справочниках требуют аудита; текст назначения платежа — шумный.                                                                                                                                          |
| Право использовать                   | Банковская тайна и персональные данные. Цель — ПОД/ФТ, правовое основание и допустимость обработки в конкретном контуре подтверждают комплаенс и DPO, а не архитектор.                                                             |
| **Вердикт**                          | **Разрыв с планом закрытия.** Разрыв не в объёме, а в наличии сильных меток и в смещении отбора. Закрывается программой разметки (контрольная выборка + разобранная очередь), а не закупкой данных.                                |

## Инициатива 18. Извлечение финансовых показателей из документов

| Поле                        | Оценка                                                                                                                                                       |
|-----------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Решение                     | Предзаполнение карточки кредитной заявки для андеррайтинга.                                                                                                  |
| Объект и гранулярность      | Документ; единица — значение конкретного поля в документе.                                                                                                   |
| Источник и владелец         | Пакеты кредитных заявок (PDF, сканы, Excel, фото), справочник форм и показателей. Владелец — кредитный блок и ИТ; доступ через комплаенс и DPO.              |
| Источник правильного ответа | Исправления андеррайтера в карточке (массовый, но слабый след) и сверка с официальной отчётностью (сильный, но неполный). Источники нужно хранить раздельно. |
| Доступность признаков       | Документы доступны в момент разбора заявки.                                                                                                                  |
| Разметка                    | Слабая разметка из исправлений андеррайтера; при пилоте — доразметка выборки по гайдлайну.                                                                   |
| Смещение отбора             | Умеренное: андеррайтер правит то, что заметил, а не случайную выборку. Для оценки нужна отдельная контрольная выборка.                                       |
| Репрезентативность          | Покрытие зависит от типов документов. На пилоте — один массовый тип, дающий основную долю пакета.                                                            |
| Объём                       | Достаточный архив пакетов; объём по редким формам может быть мал.                                                                                            |
| Качество                    | Разнородные форматы, сканы разного качества, возможны дубли.                                                                                                 |
| Право использовать          | Банковская тайна, персданные поручителей-физлиц. Нужно заключение комплаенса и DPO по цели, основанию, региону обработки и договору с обработчиком.          |
| **Вердикт**                 | **Можно начинать пилот** на одном типе документа с обязательной верификацией андеррайтером.                                                                  |

## Инициатива 5. Маршрутизация обращений

| Поле                        | Оценка                                                                                                                                                 |
|-----------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------|
| Решение                     | Маршрутизация обращения в очередь отдела.                                                                                                              |
| Объект и гранулярность      | Обращение (тикет).                                                                                                                                     |
| Источник и владелец         | CRM / helpdesk: текст обращения, история маршрутов, фактические отделы. Владелец — клиентский сервис.                                                  |
| Источник правильного ответа | История маршрутов и закрытий в CRM; корректировки оператора при перемаршрутизации.                                                                     |
| Доступность признаков       | Текст обращения доступен в момент поступления.                                                                                                         |
| Разметка                    | Метки есть в CRM; нужна очистка от разовых ручных схем маршрутизации и определение «правильного» отдела.                                               |
| Смещение отбора             | Умеренное: история отражает текущие правила, а не случайную выборку. Для приёмки — отдельная контрольная выборка.                                      |
| Репрезентативность          | Зависит от канала. На пилоте — один канал с наибольшим объёмом.                                                                                        |
| Объём                       | Достаточный для обучения классификатора.                                                                                                               |
| Качество                    | Текст шумный, возможны дубли и неоднозначные обращения.                                                                                                |
| Право использовать          | Персданные в тексте обращения. Стандартные меры защиты; отдельного правового барьера для пилота нет, но политика хранения и доступа согласуется с DPO. |
| **Вердикт**                 | **Можно начинать пилот** на одном канале.                                                                                                              |
