# Паспорт инициативы №18. Разделы 2–5

## Раздел 2. Постановка

| Поле                        | Содержание                                                                                                                                                                 |
|-----------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Бизнес-действие             | Предзаполнение карточки кредитной заявки; андеррайтер подтверждает или правит значения.                                                                                    |
| Объект и единица решения    | Документ; единица — значение поля.                                                                                                                                         |
| Момент                      | Пачкой при загрузке пакета; по запросу андеррайтера при правке.                                                                                                            |
| Операция                    | Извлечение.                                                                                                                                                                |
| Модальность                 | Документ, изображение, таблица.                                                                                                                                            |
| Выход модели                | Структура «поле → значение, уверенность, страница, координаты».                                                                                                            |
| Бизнес-выход                | Карточка с подсветкой низкой уверенности.                                                                                                                                  |
| Источник правильного ответа | Исправления андеррайтера (слабая разметка) + сверка с официальной отчётностью (сильная, но неполная).                                                                      |
| Конвейер                    | Детерминированные: OCR-движок, проверка обязательности, арифметические контроли, сверка со справочником. Обучаемые: layout-детекция, извлечение пар. Человек: верификация. |
| Альтернативные постановки   | Только OCR без извлечения; LLM end-to-end без структуры; отдельные шаблоны под каждую форму. Различающий вопрос: какие документы дают 80% пакета?                          |

## Раздел 3. Оценка качества

| Поле                | Содержание                                                                                                            |
|---------------------|-----------------------------------------------------------------------------------------------------------------------|
| Бизнес-метрика      | Сокращение времени разбора пакета; снижение ошибок ввода.                                                             |
| Положительный класс | Поле извлечено верно.                                                                                                 |
| Метрика под решение | **End-to-end accuracy** — доля документов, где все обязательные поля верны; отдельно — accuracy на критических полях. |
| Baseline            | Ручной ввод / текущий OCR без извлечения.                                                                             |
| Проверочная выборка | Отложенная выборка документов, не использованных при обучении, сбалансированная по типам.                             |
| Рабочая точка       | Порог уверенности, ниже которого поле уходит на ручную проверку.                                                      |
| Показатели          | End-to-end accuracy, доля low-confidence, время андеррайтера.                                                         |
| Цена ошибок         | Неверное значение → неверное кредитное решение; пропуск → ручная правка.                                              |
| Guardrails          | Доля критических ошибок не выше согласованного уровня.                                                                |

## Раздел 4. Готовность данных

| Поле                        | Содержание                                              |
|-----------------------------|---------------------------------------------------------|
| Решение                     | Предзаполнение карточки.                                |
| Объект и гранулярность      | Документ / поле.                                        |
| Источник и владелец         | Пакеты заявок; владелец — кредитный блок.               |
| Источник правильного ответа | Исправления андеррайтера + официальная отчётность.      |
| Доступность признаков       | Да, в момент разбора.                                   |
| Разметка                    | Слабая из исправлений; доразметка на пилоте.            |
| Смещение отбора             | Умеренное; корректируется контрольной выборкой.         |
| Репрезентативность          | Пилот на массовом типе документа.                       |
| Объём                       | Достаточный; редкие формы могут быть мало представлены. |
| Качество                    | Разнородные форматы, сканы, дубли.                      |
| Право использовать          | Комплаенс и DPO; договор обработки.                     |
| **Вердикт**                 | **Можно начинать пилот.**                               |

## Раздел 5. Карточка эксперимента

| Поле                            | Содержание                                                                                                                  |
|---------------------------------|-----------------------------------------------------------------------------------------------------------------------------|
| Где именно теряем               | На нестандартных формах и сканах низкого качества; на полях, которые андеррайтер правит чаще всего.                         |
| Гипотеза причины                | Layout-модель + LLM на low-confidence даст end-to-end accuracy выше baseline без роста критических ошибок.                  |
| Конкурирующие объяснения        | Проблема в OCR, а не в извлечении; данных мало; проблема в справочнике показателей.                                         |
| Рычаг                           | OCR-качество · layout-модель · LLM на low-confidence · порог уверенности.                                                   |
| Дешёвый различающий эксперимент | Сравнить на одном типе документа: OCR-only, layout-модель, гибрид с LLM; замерить end-to-end accuracy и долю ручных правок. |
| Ожидаемый эффект                | Сокращение времени разбора и снижение ошибок на согласованную величину.                                                     |
| Стоимость проверки              | Разметка, GPU-время, 4–6 недель.                                                                                            |
| Критерий остановки              | Если end-to-end accuracy ниже порога на массовом типе — пилот не масштабируем.                                              |
