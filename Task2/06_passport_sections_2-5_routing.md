# Паспорт инициативы №5. Разделы 2–5

## Раздел 2. Постановка

| Поле                        | Содержание                                                                                                                                                  |
|-----------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Бизнес-действие             | Автоматическая маршрутизация обращения в очередь отдела.                                                                                                    |
| Объект и единица решения    | Обращение (тикет).                                                                                                                                          |
| Момент                      | Real-time.                                                                                                                                                  |
| Операция                    | Многоклассовая классификация текста.                                                                                                                        |
| Модальность                 | Текст.                                                                                                                                                      |
| Выход модели                | Распределение вероятностей по отделам, top-1, top-3.                                                                                                        |
| Бизнес-выход                | Тикет в очереди отдела; low-confidence — на ручную сортировку.                                                                                              |
| Источник правильного ответа | История маршрутов и закрытий в CRM; корректировки оператора.                                                                                                |
| Конвейер                    | Детерминированные: правила по каналу/типу клиента, справочник отделов, порог. Обучаемые: классификатор текста. Человек: low-confidence и перемаршрутизация. |
| Альтернативные постановки   | Только правила по ключевым словам; multi-label; маршрутизация на сотрудника. Различающий вопрос: что считаем ошибкой — неверный отдел или задержку?         |

## Раздел 3. Оценка качества

| Поле                | Содержание                                                                                 |
|---------------------|--------------------------------------------------------------------------------------------|
| Бизнес-метрика      | Время до первого ответа; доля перемаршрутизаций.                                           |
| Положительный класс | Правильный отдел (определяется по CRM).                                                    |
| Метрика под решение | **macro-F1** и **top-3 accuracy**; доля перемаршрутизаций.                                 |
| Baseline            | Текущая ручная сортировка / правила по ключевым словам.                                    |
| Проверочная выборка | Отложенная выборка обращений, не использованных при обучении, сбалансированная по отделам. |
| Рабочая точка       | Порог уверенности для автоматической маршрутизации.                                        |
| Показатели          | macro-F1, top-3, доля low-confidence, доля перемаршрутизаций.                              |
| Цена ошибок         | Неверный отдел → задержка, обратима; критических правовых последствий нет.                 |
| Guardrails          | Доля перемаршрутизаций не выше baseline.                                                   |

## Раздел 5. Карточка эксперимента

| Поле                            | Содержание                                                                                               |
|---------------------------------|----------------------------------------------------------------------------------------------------------|
| Где именно теряем               | На неоднозначных обращениях и обращениях, касающихся двух отделов.                                       |
| Гипотеза причины                | Fine-tuned RuBERT + LLM на low-confidence даст macro-F1 выше baseline и снизит перемаршрутизации.        |
| Конкурирующие объяснения        | История маршрутов грязная; «правильный» отдел определён неверно; проблема в канале.                      |
| Рычаг                           | Модель (RuBERT vs LLM) · порог · multi-label.                                                            |
| Дешёвый различающий эксперимент | Сравнить RuBERT, гибрид RuBERT+LLM и baseline на одном канале.                                           |
| Ожидаемый эффект                | Рост macro-F1 и снижение перемаршрутизаций.                                                              |
| Стоимость проверки              | Разметка/очистка, GPU-время, 3–4 недели.                                                                 |
| Критерий остановки              | Если macro-F1 ниже порога, но top-3 хорош — оставить top-3; если и top-3 плох — пересмотреть постановку. |
