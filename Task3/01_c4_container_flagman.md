# C4 Container — флагман: сервис приоритизации очереди финмониторинга

## Назначение

Приоритизировать очередь операций для службы финмониторинга: на входе — операция по счёту, на выходе — позиция в очереди
и пояснение. Решение по операции принимает сотрудник по действующей процедуре.

## Диаграмма

C4 Container — `diagrams/01_container_flagman.puml`. Границы доверия помечены `[TBx]` на связях и в legend. Отдельная
карта границ — `diagrams/05_trust_boundaries_flagman.puml`.

## Контейнеры и их роли

| Контейнер                   | Тип                      | Роль                                                                                                |
|-----------------------------|--------------------------|-----------------------------------------------------------------------------------------------------|
| Ingestion & Feature Builder | Сервис                   | CDC из АБС, нормализация операции, онлайн- и офлайн-признаки, эмбеддинги текста назначения платежа. |
| Feature Store               | Хранилище                | Онлайн- и офлайн-признаки, версии фичей.                                                            |
| Rules Engine                | Сервис                   | Пороговые правила, лимиты, списки, структурные проверки — детерминированно.                         |
| Scoring Service             | Сервис с моделью         | Риск-скор, калибровка, SHAP-факторы.                                                                |
| Decision & Priority Service | Сервис                   | Стык правил и модели, guardrails, приоритет, выходной контракт.                                     |
| Prioritized Queue           | Хранилище + очередь      | Очередь с приоритетом, пояснениями, статусами.                                                      |
| Рабочее место ФМ            | Существующий UI процесса | Показ очереди и пояснений, фиксация решения человеком.                                              |
| Control Sample Generator    | Сервис                   | Вероятностная стратифицированная выборка операций для разметки.                                     |
| Label Store                 | Хранилище                | Разметка: разобранная очередь + контрольная выборка, версии гайдлайна.                              |
| Training Pipeline           | Пакетный сервис          | Обучение, валидация, калибровка, оценка на контрольной выборке.                                     |
| Model Registry              | Хранилище                | Версии моделей, артефакты, происхождение весов и зависимостей.                                      |
| Monitoring & Audit          | Сервис                   | Качество данных, дрейф, метрики очереди и бизнес-метрики, аудит решений.                            |

## Границы доверия на схеме

Точки, где данные покидают контур или входит недоверенный контент. На C4-диаграмме отмечены пунктиром и метками на
связях; конкретные требования — в `09_trust_boundaries_threats.md`.

| Метка | Что за граница                                                     |
|-------|--------------------------------------------------------------------|
| TB1   | Вход внешнего сигнала KYC в контур банка                           |
| TB2   | Вход из АБС и справочников (legacy, разные права доступа)          |
| TB3   | Недоверенный клиентский текст «назначение платежа» на входе модели |
| TB4   | Артефакты модели, веса и зависимости (supply chain)                |
| TB5   | Выход модели в рабочее место сотрудника                            |
| TB6   | Данные разметки (ПДн, банковская тайна) в training pipeline        |
| TB7   | Телеметрия и аудит-логи за пределы сервиса                         |

## Режим обработки

| Звено                | Режим                        | Последствия                                                             |
|----------------------|------------------------------|-------------------------------------------------------------------------|
| Ingestion и признаки | Потоковый (near-real-time)   | Задержка секунды; повторы идемпотентны по `operation_id`.               |
| Rules Engine         | Синхронный вызов из decision | Детерминированный, без повторов.                                        |
| Scoring Service      | Синхронный вызов с таймаутом | При таймауте — фолбэк на правила (см. `07_fallback_and_automation.md`). |
| Decision & Priority  | Синхронно на операцию        | Формирует контракт; пишет в очередь.                                    |
| Prioritized Queue    | Асинхронная                  | Человек разбирает верхушку; очередь пересчитывается пачкой.             |
| Training Pipeline    | Пакетный, по расписанию      | Не влияет на онлайн-путь.                                               |

**Почему так:** онлайн-путь должен быть коротким и детерминированным по поведению; всё, что может занять время
(разметка, обучение, пересчёт очереди), вынесено в асинхронные и пакетные звенья. Работа человека не блокируется
недоступностью модели — очередь уже сформирована, при сбое скоринга приоритет считается по правилам и сумме.

## Что моделью не является

- Пороговые правила, лимиты, справочники, проверка по спискам, структурные проверки — детерминированный код.
- Приоритет в очереди — правило поверх скора и срабатываний правил.
- Решение по операции — человек.
