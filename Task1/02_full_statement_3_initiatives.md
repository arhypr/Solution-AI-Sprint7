## Инициатива 1. Автоматически выявлять подозрительные операции по счетам

**Вердикт:** Гибрид. Флагман, сквозной ADR.

### Раздел 1. Полная постановка

| Поле                                      | Содержание                                                                                                                                                                                                                                                                                                                                                                         |
|-------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Инициатива без слова «AI»                 | На входе — операция по счёту (сумма, назначение платежа, контрагент, ОКВЭД, дата, канал) и история клиента. На выходе — риск-скор операции и место в очереди финмониторинга.                                                                                                                                                                                                       |
| Какое действие изменится                  | Очередь разбора (около 35 тыс. помеченных операций в месяц) сортируется по риску, а не только по сумме. 25 сотрудников разбирают верхушку очереди; часть операций по действующей процедуре уходит на углублённое расследование.                                                                                                                                                    |
| Где именно нужна обучаемая закономерность | Ранжирование операций по вероятности схемы по слабым и косвенным признакам, включая текст назначения платежа в свободной форме. Пороговые правила, справочники, лимиты и проверка по спискам остаются детерминированными.                                                                                                                                                          |
| Чего не хватает, допущения                | Нет эталона «схема / не схема». Есть три разных следа: эскалация на расследование (~400 в месяц), исход расследования и единичные формально подтверждённые случаи с лагом в месяцы. Отбор проверенных операций смещён пороговыми правилами: непроверенная операция не равна чистой. Допущение: слабые следы пригодны для обучения с учителем при явной работе со смещением отбора. |
| Вердикт                                   | Гибрид                                                                                                                                                                                                                                                                                                                                                                             |

### Раздел 2. Постановка

| Поле                        | Содержание                                                                                                                                                                                                                                                                                                                                                           |
|-----------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Бизнес-действие             | Приоритизация очереди финмониторинга. При подтверждении — эскалация или отказ в проведении операции строго по действующей процедуре; решение принимает человек.                                                                                                                                                                                                      |
| Объект и единица решения    | Операция по счёту. Одна операция — один риск-скор и один приоритет.                                                                                                                                                                                                                                                                                                  |
| Момент                      | Near-real-time при появлении операции, плюс пачечный пересчёт очереди; разбор — человеком в рабочем режиме.                                                                                                                                                                                                                                                          |
| Операция                    | Аномалия и ранжирование (бинарная классификация с сортировкой по скору).                                                                                                                                                                                                                                                                                             |
| Модальность                 | Таблица (транзакции, справочники, ОКВЭД, канал) и текст (назначение платежа).                                                                                                                                                                                                                                                                                        |
| Выход модели                | Риск-скор от 0 до 1 и позиция в топ-K очереди; для сотрудника — набор сработавших признаков.                                                                                                                                                                                                                                                                         |
| Бизнес-выход                | Очередь с приоритетом и пояснением, почему операция наверху. Не блокировка: блокировка остаётся действием процесса по регламенту.                                                                                                                                                                                                                                    |
| Источник правильного ответа | Эскалация на расследование (слабый след), исход расследования (сильнее), формально подтверждённые случаи (единицы, лаг месяцы). Готового эталона нет, и путать эти следы между собой нельзя.                                                                                                                                                                         |
| Конвейер                    | Детерминированные звенья: пороговые правила, справочники и лимиты, проверка по спискам. Обучаемые звенья: скоринг операции, эмбеддинги текста назначения, ранжирование. Человек: финальное решение по каждой операции верхушки очереди.                                                                                                                              |
| Альтернативные постановки   | (а) Классификация «эскалация / не эскалация» — предсказываем действие сотрудника, а не схему; (б) поиск аномалий без меток; (в) только правила плюс приоритизация по сумме как baseline. Различающий вопрос бизнесу: что оптимизируем — долю подтверждённых схем в верхушке очереди, число пропущенных подтверждённых случаев или снятую нагрузку на 25 сотрудников? |

## Инициатива 18. Извлекать финансовые показатели из неструктурированных бухгалтерских документов и банковских выписок

**Вердикт:** Гибрид.

### Раздел 1. Полная постановка

| Поле                                      | Содержание                                                                                                                                                                                                                                             |
|-------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Инициатива без слова «AI»                 | На входе — пакет документов: PDF, сканы, фотографии, Excel и выгрузки из бухгалтерских систем. На выходе — структурированный набор финансовых показателей (выручка, расходы, долг, обороты) в карточке кредитной заявки.                               |
| Какое действие изменится                  | Андеррайтер получает предзаполненную карточку и проверяет значения, а не переносит цифры руками. Среднее время разбора пакета (около 1,5 часа) сокращается, снижается доля ошибок ввода.                                                               |
| Где именно нужна обучаемая закономерность | Извлечение значений из неструктурированных форм и сканов: детекция layout, привязка «показатель → значение», нормализация единиц и периодов. Проверка обязательности полей, арифметические контроли и сверка со справочником форм — детерминированные. |
| Чего не хватает, допущения                | Нужен перечень обязательных для андеррайтинга показателей, архив исправлений андеррайтера и единый справочник форм. Допущение: исправления андеррайтера можно использовать как слабую разметку.                                                        |
| Вердикт                                   | Гибрид                                                                                                                                                                                                                                                 |

### Раздел 2. Постановка

| Поле                        | Содержание                                                                                                                                                                                                                                                                                 |
|-----------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Бизнес-действие             | Предзаполнение карточки кредитной заявки для андеррайтинга с подсветкой полей низкой уверенности.                                                                                                                                                                                          |
| Объект и единица решения    | Документ; единица решения — значение конкретного поля в документе.                                                                                                                                                                                                                         |
| Момент                      | Пачкой при загрузке пакета, плюс по запросу андеррайтера при ручной правке.                                                                                                                                                                                                                |
| Операция                    | Извлечение (структурирование неструктурированного документа).                                                                                                                                                                                                                              |
| Модальность                 | Документ, изображение, таблица.                                                                                                                                                                                                                                                            |
| Выход модели                | Структура «поле → значение, уверенность, страница и координаты фрагмента».                                                                                                                                                                                                                 |
| Бизнес-выход                | Заполненная карточка заявки с подсветкой низкой уверенности; андеррайтер подтверждает или правит.                                                                                                                                                                                          |
| Источник правильного ответа | Исправления андеррайтера в карточке (массовый, но слабый след) и сверка с официальной отчётностью (сильный, но неполный по охвату). Оба источника нужно хранить раздельно.                                                                                                                 |
| Конвейер                    | Детерминированные звенья: OCR-движок, проверка обязательности полей, арифметические контроли (активы равны пассивам), сверка со справочником форм. Обучаемые звенья: детекция layout, извлечение пар «показатель → значение», классификация типа документа. Человек: верификация значений. |
| Альтернативные постановки   | (а) Только OCR без извлечения — андеррайтер ищет сам; (б) LLM end-to-end без структуры и уверенности; (в) отдельные шаблоны под каждую форму. Различающий вопрос бизнесу: какие документы дают 80% пакета и допустима ли ручная доразметка недостающих?                                    |

## Инициатива 5. Маршрутизировать входящие обращения по нужным отделам

**Вердикт:** ML-кандидат.

### Раздел 1. Полная постановка

| Поле                                      | Содержание                                                                                                                                                                                                               |
|-------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Инициатива без слова «AI»                 | На входе — текст обращения из чата, почты или веб-формы. На выходе — отдел и очередь, в которую обращение попадает.                                                                                                      |
| Какое действие изменится                  | Обращение уходит в нужный отдел без ручной сортировки: сокращается время до первого ответа и число перемаршрутизаций.                                                                                                    |
| Где именно нужна обучаемая закономерность | Текстовая классификация по истории обращений и фактическому отделу-исполнителю. Справочник отделов и правила по каналу и типу клиента — детерминированные.                                                               |
| Чего не хватает, допущения                | Нужно определение «правильного» отдела: первый обработавший или закрывший. Нужна политика по неоднозначным обращениям, которые касаются двух отделов. Допущение: история маршрутов в CRM достаточно чистая для обучения. |
| Вердикт                                   | ML-кандидат                                                                                                                                                                                                              |

### Раздел 2. Постановка

| Поле                        | Содержание                                                                                                                                                                                                                                                                        |
|-----------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Бизнес-действие             | Автоматическая маршрутизация обращения в очередь отдела.                                                                                                                                                                                                                          |
| Объект и единица решения    | Обращение (тикет); одно обращение — одно решение о маршруте.                                                                                                                                                                                                                      |
| Момент                      | Real-time при поступлении обращения.                                                                                                                                                                                                                                              |
| Операция                    | Категоризация (многоклассовая классификация текста).                                                                                                                                                                                                                              |
| Модальность                 | Текст.                                                                                                                                                                                                                                                                            |
| Выход модели                | Распределение вероятностей по отделам и top-1.                                                                                                                                                                                                                                    |
| Бизнес-выход                | Тикет в очереди выбранного отдела; при низкой уверенности — метка «на ручную сортировку».                                                                                                                                                                                         |
| Источник правильного ответа | История маршрутов и закрытий в CRM, а также корректировки оператора при перемаршрутизации.                                                                                                                                                                                        |
| Конвейер                    | Детерминированные звенья: правила по каналу, типу клиента и ключевым словам, справочник отделов, порог уверенности. Обучаемые звенья: классификатор текста. Человек: разбор low-confidence и перемаршрутизация.                                                                   |
| Альтернативные постановки   | (а) Только правила по ключевым словам; (б) multi-label вместо single-label, если обращение реально касается двух отделов; (в) маршрутизация на конкретного сотрудника, а не отдел. Различающий вопрос бизнесу: что считаем ошибкой — неверный отдел или задержку в маршрутизации? |
