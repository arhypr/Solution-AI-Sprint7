## Краткий вывод

**Симптом:** через три месяца после выхода в сегмент селлеров маркетплейсов precision@K в очереди финмониторинга просел.

**Диагноз:** это не поломка модели, а **сдвиг домена**: модель обучена на старых клиентах и не видела профиль селлеров
(много мелких поступлений, возвраты, расчёты с самозанятыми). Её выученный признак «подозрительности» — дробление и
мелкие поступления — для селлеров является нормой. Это **concept drift** для нового сегмента, усиленный **rule
interference** (правила тоже флудят очередь) и **text drift** (незнакомые формулировки назначения платежа). Feature
staleness и адаптация мошенников — возможные, но не подтверждённые без разметки.

**Почему мониторинг не поймал:** метрики считались агрегированно по всем сегментам, состав очереди не отслеживался,
покрытие признаков по сегментам не измерялось. Деградация стала видна только когда «разбавила» общую метрику.

**Что чиним:** сегментный резолвер, сегментно-осведомлённый мониторинг, сегментно-стратифицированный регрессионный
набор, shadow/canary rollout с автоматическим откатом по сегментным guardrails.
