# Дешёвые различающие эксперименты

Принцип: сначала бесплатные или почти бесплатные проверки на уже имеющихся данных, потом — платная разметка. Каждый
эксперимент должен **различать** гипотезы, а не подтверждать любимую.

## Сводная таблица

|----|---------------------------------------------------------------------|----------------------------------------|----------|------------------------------------------|-----------------------------------------------------------------------------------------------|

**Итого до платной разметки:** 5–6 рабочих дней и почти 0 ₽. Этого достаточно, чтобы отсечь H1–H3, H6, H8 и сузить до
H4/H5/H7. Дальше — только E6 (label audit), потому что H4, H5 и H7 различаются только по земле.

## Детали по экспериментам

### E1. Сегментный разрез метрик

**Что делаем.** Вводим детерминированный сегментный тег: `seller` / `non_seller`. Признаки селлера: ОКВЭД из списка
маркетплейс-торговли, контрагент из списка площадок (Ozon, Wildberries, Яндекс Маркет и т.п.), паттерн текста («выплата
от…», «возврат по заказу…», «расчёт с самозанятым…»). Тег не ML, а справочник + правило — дёшево и объяснимо.

Считаем precision@K, override rate, escalation rate, fallback rate отдельно для `seller` и `non_seller` за последние 6
месяцев.

**Что различает.** Если падение только в `seller` — причина локальная для сегмента (H1–H7). Если падение и в
`non_seller` — системная (H8 или H4 для всех).

**Стоимость.** Аналитик 1–2 дня. Справочник сегментов — из открытых источников и внутренних списков контрагентов.

### E2. Аудит покрытия признаков

**Что делаем.** Для каждого признака считаем долю null, default, stale (старше окна) отдельно по сегментам.

**Что различает.** Если у селлеров доля null/default/stale высокая по history-признакам — H2 (нет истории). Если
значения есть, но分布 сдвинут — H1 (covariate shift). Если аномалии в сырых данных — H8.

### E3. OOD score и PSI

**Что делаем.** Считаем OOD score (Isolation Forest на признаках, обученный на старом распределении) и PSI по ключевым
признакам для селлеров vs старых клиентов.

**Что различает.** Высокий OOD/PSI → H1. Низкий OOD при падении качества → H4 (вход в распределении, но зависимость
изменилась).

### E4. OOV и embedding distance

**Что делаем.** Токенизируем назначение платежа, считаем OOV rate (доля токенов вне обучающего словаря) и среднее
косинусное расстояние до центроидов обучающих эмбеддингов по сегментам.

**Что различает.** Высокий OOV/расстояние → H3. Низкий → текст ни при чём.

### E5. Разрез top-K по источнику

**Что делаем.** Для каждой операции в top-K фиксируем, чем она поднята: правилом, моделью или обоими. Считаем долю
rule-driven кейсов по сегментам.

**Что различает.** Если у селлеров доля rule-driven кейсов в top-K резко выросла, а модельный скор этих кейсов низкий —
H6. Если модельные кейсы тоже просели — H4/H5.

### E6. Label audit 200 операций селлеров

**Что делаем.** Берём 200 операций селлеров из top-K (стратифицированно: rule-driven и model-driven, разные подтипы) и
размечаем вручную по гайдлайну: подтверждённая схема / ложное срабатывание / неоднозначно. Сравниваем с такой же
выборкой старых клиентов.

**Что различает.**

- Много ложных, мало подтверждённых → H4 (concept drift) или H5 (артефакт оценки).
- Много подтверждённых новых схем → H7 (адаптация мошенников).
- H4 vs H5: если при разбивке по источнику эскалации модельная часть точна, а общая — нет, это H5.

**Стоимость.** 200 × 12 мин × 1 500 ₽/час ≈ 60 000 ₽, 1 неделя. Единственный платный эксперимент на этапе диагностики.

### E7. Data quality по сегментам

**Что делаем.** Null rate, ошибки парсинга, длина текста, полнота полей — по сегментам.

**Что различает.** Аномалии у селлеров → H8 (pipeline break).

### E8. Контрфактическое сравнение

**Что делаем.** Берём старых клиентов и скорим старой и новой моделью (или текущей моделью до и после выхода в сегмент).
Сравниваем распределение скоров.

**Что различает.** Если скоры старых клиентов не сдвинулись — модель в порядке, проблема в сегменте. Если сдвинулись —
модель деградировала системно (например, переобучение на загрязнённых данных).

## Порядок запуска

1. E1 (день 1–2) — отсекает «деградация везде».
2. E2, E3, E4, E7 (день 3–5) — параллельно, отсекают H1, H2, H3, H8.
3. E5 (день 5–6) — отсекает H6.
4. E8 (день 5–6) — подтверждает, что модель не «сломалась» системно.
5. E6 (неделя 2) — различает H4, H5, H7. Единственный платный шаг, запускается только после того, как предыдущие отсекли
   остальное.

**Критерий остановки диагностики:** когда осталась одна гипотеза, которая объясняет все наблюдаемые сигналы, и ни одна
другая не объясняет. Тогда — правки архитектуры (см. `04_architecture_fixes.md`).
